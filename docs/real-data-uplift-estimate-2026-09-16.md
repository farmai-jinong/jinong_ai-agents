# 실 음성데이터 추가 시 성능 개선 추정 (2026-09-16)

실통화 녹음이 더 들어오면 무엇이 얼마나 좋아지는지를 **지표별·데이터량별**로 추정한 표다.
전부 기존 실측(사다리·A/B·평가 저널)에서 기울기를 빌려 외삽한 값이고, 새로 측정한 것은 없다.
승격·일정 근거로 쓰지 말고, 실데이터가 실제로 도착하면 이 문서의 수치를 갱신한다.

앵커에서 나오는 결론 하나: **"실 음성데이터 추가"의 효과는 그 데이터에 전사 라벨이 붙는지에 따라 완전히 갈린다.**

### 읽는 법

- STT 는 데이터량에 가장 직접적으로 반응한다. **2배만 되어도 계획서가 4축(라벨·컨텍스트·후보정·백본) 전부에 기대하는
  누적치(.1167→.095~.105)의 절반 이상**을 데이터 한 축이 낸다. 목적지 .05 는 10배 + 라벨 규약 정렬 + 더 큰 백본이 맞물려야 하는 수치다(계획서 (x)).
- 영농일지 점수는 데이터량에 **간접적으로만** 반응한다. LLM(Gemini)은 학습하지 않으므로 실통화는 ① STT 를 통해, ② 평가셋을
  넓혀 구조 결함을 드러내는 경로로만 점수를 올린다. ②가 ①보다 크지만, ②는 **녹음이 아니라 "정답 일지가 붙은 녹음"** 이 필요하다.
- **연출 대본 5건의 0.9033 은 실통화 점수가 아니다.** 실통화는 잡담 비중·복수 작물·8 kHz·farmos 조회 불일치가 더 크므로
  실통화 정답셋으로 처음 재면 **0.80 ~ 0.88 부근**에서 시작할 가능성이 크다(추정, 미측정). 위 표의 "+" 는 그 새 기준선 위의 증분이다.

## 3. 유입 속도로 환산하면

| 경로 | 속도 | 2× 도달 | 10× 도달 | 라벨 |
|---|---|---|---|---|
| 앱 보이스톡 (prod, 60 초 이상) | 주 ~15 분 (4주 25건) | **~36 주** | ~5.5 년 | 없음 — 챔피언 전사만 있음 |
| 콜센터 상담 재익스포트 (audio_labeler 검수) | 회당 수 시간 단위 | 1회 | 수 회 | 있음 (검수 전사) |

즉 앱 유입만으로는 STT 학습 축의 2× 효과를 연내 측정할 수 없다. 앱 실통화의 당장 가치는 **평가셋**이다 — 60 초 이상 25건 중
20~50건에 정답 일지를 붙이면 노이즈 밴드가 ±0.02 → ±0.006 으로 줄고, 지금까지 밴드에 묻혀 거부된 크기(0.004~0.013)의
개선이 판정 가능해진다. 라벨 비용은 통화 1건당 정답 일지 작성 30~60 분으로 잡는다.

## 4. 전제와 함정

- 고유량 사다리는 0.25×~1.0× 세 점이고 노출량을 고정한 실측이다. **1× 위는 외삽**이며 세대 #14 arm T 는 곡률을 재려다
  과반복 아티팩트로 외삽치가 오히려 비관적이었음을 확인했다 — 실제 기울기가 더 가파를 수 있으나 표에는 반영하지 않았다.
- 라벨 없는 앱 녹음을 챔피언 전사로 의사라벨링해 학습에 넣는 경로는 **측정된 적이 없다**. 표에 넣지 않았다.
- STT 개선은 재학습 → 승격 게이트(페어드 CI 상한 < 0, ko 가드 +.0033) 를 통과해야 agents 에 도달한다. 9/8 이후 :8102 가 :8100 을
  위임하므로 승격은 즉시 반영된다.
- 판정 노이즈 밴드는 judge×3 기준이다. judge×1 로 재면 밴드가 1.5배 넓다.
- prod EMPTY 51건은 60 초 미만 테스트 통화가 대부분이다(60 초 이상에서 EMPTY 1/25). EMPTY 율은 실통화 품질 지표로 읽지 말 것.

## 5. 갱신 규칙

실통화가 실제로 들어오면 (a) 라벨 있는 시간, (b) 정답 일지가 붙은 건수를 §0 에 적고, §2 의 해당 열을 실측으로 바꾼다.
실측이 추정 범위를 벗어나면 §1 의 기울기를 먼저 고친다.
