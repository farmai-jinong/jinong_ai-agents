# STT 용어 오청 복구 — LLM 사후 교정 실험 (2026-09-06)

## 왜 했나

`:8105` 후처리 엔진(자모 fuzzy 검색 → 용어 컨텍스트 2차 전사)은 실통화 2,354발화에서 이득 0 이다
([09-03 문서](./stt-postprocess-effectiveness-2026-09-03.md)). 원인은 사전이 아니라 검색이다 — 정답 용어 538개가 전부
카탈로그에 있는데, 검색이 **자모 편집거리 하나** 라서 오청 128건 중 92건이 편집 예산 밖(`탄저병↔탄두병` 예산 1 초과,
`쏘일킹↔수독` 6편집)이고, 예산을 풀면 오탐이 폭증한다(스윕 4-5-10 .1169 채택 / 2.5-6-10 .1227).

이 리포에는 그 엔진을 개선하는 하네스가 없다. `voice_eval` 은 STT 를 고정 입력으로 놓고 재고, 자가 개선 루프는 `stt`
원인 셀을 명시적으로 뺀다(`optimize/diagnose.py`). 엔진 하네스(`jinong_gpu/stt-serve/ctx_replay.py`·`stt041_analysis.py`)는
사람이 한 점씩 돌리는 스윕이고 튜닝으로는 못 푼다는 것이 이미 측정됐다.

그래서 검색 대신 **전사 완료본 + 카탈로그(품종 제외 4,106건 ≈ 14k 토큰) 를 LLM 에 통째로 주고, 일상 한국어로 말이 안 되는
어절만 발음·문맥이 맞는 카탈로그 용어로 바꾸는 치환 목록** 을 내게 했다. 두 리포 어디에도 시도 기록이 없는 접근이다.
게이트웨이 `terms.correct` 의 fuzzy 치환이 모든 임계에서 악화된 것은 자모 규칙의 결과라 반증이 아니다.

풀어야 하고, 남은 오청은 더 어려운 것들이다. **LLM 교정을 쓴다면 `:8105` 2패스 대신** 이지 위에 얹는 게 아니다.

## 오탐·거부에서 배운 것

- **카탈로그 구멍이 곧 오탐이다.** 남은 FP 는 전부 "정답 용어가 카탈로그에 없어서 LLM 이 가장 가까운 카탈로그 항목을 고른"
  경우다: `나오와이·나노아이→나노진`(정답 `나노아이` 없음), `가루의약→가루비네`·`아리랑→아리타로닐`(`가루이` 단독 표제 없음,
  `담배가루이` 만 있음). 대본에 나오는 `이리응애`(천적, `긴털이리응애` 만 있음)·`플러스칼`(비료)도 없다. 리트리버는 이런 구멍을
  "못 찾음" 으로 조용히 넘기지만 LLM 은 "가장 가까운 것" 으로 메운다 — **LLM 교정은 카탈로그 완결성에 더 민감**하다.
  운영 전이라면 카탈로그 밖 후보를 LLM 이 낼 수 있게 하고(`replacement_not_in_catalog` 거부 27건 중 `활착기`·`급액`·`팁번`·
  `이리응애` 처럼 맞는 것이 많다) 그 목록을 카탈로그 보강 큐로 쓰는 편이 낫다.
- **가드가 실제로 일했다.** LLM 은 일상어 오청(`디지몬이가→뒤집으니까`, `옹지제로→봉지째로`)과 성분명(`아조시스트로빈`)도
  고치려 든다. 카탈로그 밖 거부·불용어 거부·짧은 원문 거부가 없었으면 정밀도가 무너졌다. 신뢰도 0.7 에서 0.8 로 올리면 TP 손실
  0 에 FP 3→0.
- **표기 규약은 여기서도 남는다.** `잿빛곰팡이병`·`탄저병` 을 대본은 `잿빛곰팡이`·`탄저` 로 적는다. 그래서 채점에 "이형(TP-variant)"
  을 뒀다(병명의 `병` 접미사를 뗀 형태 또는 자모 fuzzy ≥85 로 대본에 있음). pass2 tomato 의 CER 악화도 같은 종류다 —
  `가로이→담배가루이` 는 용어로는 맞지만 그 자리의 대본은 `가루이` 라 글자 수가 는다. **CER 로 판정하면 이 방법도 :8105 처럼 묻힌다.**
- **채점 기준을 데이터를 보고 한 번 손봤다**(투명하게 적어 둔다): 계획은 "recall 상승·precision ≥ .8·CER 비악화" 였는데
  (1) recall 은 fuzzy 를 인정해 기준선이 이미 .97 이라 상승 요구가 천장에 막혀 **비하락 + exact 인식률** 로 바꿨고,
  (2) 처음 채점은 `잿빛곰팡이병` 을 FP 로 세어 precision .73 이었다 — 이형 규칙을 넣은 뒤 .88(0.7)/1.0(0.8). 이형 규칙 없이
  strict 로 봐도 0.8 에서 1.0 이다(FP 0).

## 비용

케이스당 1회 호출(세그먼트 90개 초과면 2회), 프롬프트 ~22k 토큰(카탈로그 14k 포함), 2~7초. 3분 통화 기준 `:8105` 2패스가
100초 이상 더하는 것과 대비된다. 컨텍스트 캐싱을 쓰면 카탈로그 부분은 반복 비용이 준다.
