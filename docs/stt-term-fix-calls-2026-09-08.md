# 용어 후보정(LLM)을 실통화 92통화에서 재측정 — 사전 등록 기준 미달, 갈래 종결 (2026-09-08)

`docs/stt-term-fix-2026-09-06.md` 의 5건 결과(exact .7667→.9500, FP 0)를 실통화 평가셋에서 다시 잰 것이다.
`jinong_gpu` 백로그 **stt-044(GER)** 와 같은 질문을 agents 좌표에서 물었다. 판정 기준은 **돌리기 전에** 코드에
못박았다(`voice_eval/term_fix/__main__.py` 의 `MICRO_RECALL_MIN`/`PRECISION_LENIENT_MIN`/`CER_CI_MAX`).

## 0. 먼저 — 측정 자체가 틀어져 있었다

`jinong-call` 골드 용어 538개를 카탈로그 카테고리로 가르면:

| 버킷 | 발생 | 처리 |
|---|---:|---|
| 품종(`crop_variety`) | **246 (46%)** | 제외 — 전부 부분문자열 오탐(`아시`←"아시죠", `토마`, `하우스`, `봉화`) |
| 회사(`company`) | 152 | 제외 — 표기 규약(`(주)팜한농` vs `팜한농`) 문제라 후보정 판정과 섞이면 안 된다 |
| **농약상표·병·해충** | **140** | 채택 |

`stt-041` 의 "pass-1 에서 틀린 정답 용어 128개" 는 이 오염된 538 위에서 잰 값이다. 정제 골드 140건 기준
발생 단위 오청은 **base 27건 / 챔피언 8건**이다. **CER 로는 잴 수 없는 크기**이며, 그래서 이 실험의 판정은
CER 이 아니라 도메인 용어 발생 recall + 치환 precision 이다.

정제본 `out/term-fix-calls/jinong-call-gold-domain.jsonl` 은 `jinong_gpu` **stt-043(LBL)** 입력이다.

  덤프에 `audio_path` 가 없어 `i` ↔ arrow row index 로 조인했고 `dump.ref == arrow.text` **2,354/2,354** 검증.
- 팔: `base`(agents 실경로 좌표 — 게이트웨이 diarize 는 `:8102` base 고정) / `champ`(승격 FT 참고팔).
- gemini-3.5-flash, 카탈로그 4,106(품종 제외) 통째, 통화당 1콜. **비용: in 1.81M tok / out 16k / 194초(통화당 2.3초)**.
- 프롬프트 가드 2종을 이번에 추가했다 — 5건 재측정에서 pass1 exact .7667→**1.0000**, pass2 도 처음 FP 0 (`out/term-fix-20260908-guard2/`).
  ① 계열·성분명(아졸계·아족시스트로빈)을 상표로 바꾸지 않는다 ② 상위어(가루이·이리응애)를 하위어(담배가루이·긴털이리응애)로 특정하지 않는다.

## 2. 결과 — base 좌표

| 지표 | 기준 | conf≥0.8 | **conf≥0.9** | conf≥0.95 | 사전 등록 기준 |
|---|---:|---:|---:|---:|---|
| 도메인 용어 recall(발생 140) | .8357 | .9286 | **.9286** | .8643 | ≥ .90 ✅ |
| 도메인 용어 exact | .8071 | .9143 | **.9143** | .8429 | 비하락 ✅ |
| 치환 TP / 이형 / FP | — | 41/3/28 | **38/1/8** | 15/0/2 | — |
| 치환 precision(lenient) | — | .6111 | **.8298** | .8824 | ≥ .90 ❌ |
| CER(공백제거, micro) | .1355 | .1356 | **.1348** | .1350 | — |
| ΔCER 페어드 CI95 | — | +.00006 [−.0009,+.00098] | **−.00077 [−.00163,−.00005]** | −.00056 | 상한 < +.0033 ✅ |
| **판정** | | FAIL | **FAIL** | FAIL | |

**용어는 실제로 복구된다.** exact 인식률 .8071→.9143 = 오청 27건 중 **15건 회복** — `:8105` 리트리버가
"자모 편집 예산 밖" 이라 못 풀던 구간이다(`docs/stt-postprocess-effectiveness-2026-09-03.md`). conf 0.9 에서는
공백제거 CER 도 **CI 상한이 0 아래**(−.00077 [−.00163,−.00005])로, `:8105` 의 실현 이득(−.0012)과 같은 크기다.

**그런데 오탐이 그만큼 난다.** precision(lenient) .83 은 사전 등록한 .90 에 못 미친다 → **채택하지 않는다.**

### 신뢰도 하한은 0.9 가 0.8 을 지배한다

0.8 → 0.9 로 올리면 **recall·exact 손실 0**(둘 다 .9286/.9143 그대로)에 **FP 28 → 8**. 0.8 에서 늘어나는
치환은 전부 오탐이다. 런타임 기본값을 0.9 로 올렸다(`Settings.term_fix_min_confidence`, `apply_corrections`).
실험 CLI 기본은 0.8 로 두어 과거 리포트와 비교 가능하게 남긴다.

## 3. 왜 5건에서는 FP 0 인데 84통화에서는 28건인가

5건은 **전부 제품 상담**이라 "농약 이름이 있을 자리" 만 있었다. 실통화 84통화는 대부분 잡담·안내·번호 안내이고,
LLM 은 그 자리에도 사전을 씌운다. conf≥0.9 FP 8건을 정답 발화에 대고 읽으면:

| conf | 치환 | 정답 발화 | 실제 원인 |
|---:|---|---|---|
| 0.95 | 레일단 → 레일건 | 저희가 **레일단**이라는. | 원문이 정답. `레일단` 이 카탈로그에 없어 닮은 표제로 끌려갔다 |
| 0.90 | 마세트 → 마세트300 | 팜한농에서 나오는 **마세트** 유제를요. | 원문이 정답. 카탈로그에 `마세트`·`마세트300` 이 다 있는데 숫자형을 골랐다 |
| 0.90 | 포리캡틴 → 팜한농포리캡탄 | **포리캡탄**이요. | 용어는 정답. 카탈로그 표제에 회사 접두가 붙어 있다 |
| 0.90 | 포리캡 탄전 → 팜한농포리캡탄 | 회사에서 **포리캡탄**하고는 안 나오나요? | 동상 |
| 0.95 | 농협 케미칼 → 농협케미컬 | 농약 케미칼에서 나온 거 농협에서 샀거든요. | 표기 규약(대본도 흔들린다) |
| 0.90 | 덜격제 → 돌격대 | 제가 살충제 **돌격제**라는 것을 뿌렸거든요. | `돌격제` 가 카탈로그에 없어 `돌격대` 로 |
| 0.90 | 오버런 → 오베론 | 보통 **웃거름** 같은 거 주시는 | 환각 |
| 0.90 | 결농 → 경농 | 잔류**농약 검사**에서 나타납니까? | 환각 |

**8건 중 진짜 환각은 2건뿐이다.** 나머지 6건은 카탈로그 쪽 문제 — 표제에 없는 실사용 상표(`레일단`,
`돌격제`, `아리커`, `총채싹플러스`, `풀마기골드`, `헬리앤드론`)이거나, 표제 규약(회사 접두 `팜한농포리캡탄`,
숫자 접미 `마세트300`)이다.

카탈로그를 실측하면 그 규약 문제의 크기가 나온다: **농약상표 3,540건 중 87건이 회사명 접두로 시작**하고
(`경농다찌가렌`, `팜한농포리캡탄`), 11건이 숫자로 끝난다(`마세트300`, `다이센엠-45`). 전사자는 맨 상표만 쓴다.
`stt-041` 처방 ①(법인 접두 `(주)`·㈜ 제거 85건)이 착지했지만 **회사명 접두는 손대지 않은 채로 남아 있다**.

## 4. 참고팔 — 챔피언(승격 FT) 좌표에서는 값이 사라진다

| conf | recall | exact | TP/이형/FP | precision | ΔCER CI95 | 판정 |
|---:|---|---|---|---:|---|---|
| 0.8 | .9500→.9571 | .9429→.9429 | 8/6/20 | .4118 | **+.00122 [+.00054,+.00209]** | FAIL |
| 0.9 | .9500→.9571 | .9429→.9429 | 8/3/5 | .6875 | +.00045 [+.00008,+.001] | FAIL |
| 0.95 | .9500→.9571 | .9429→.9429 | 8/0/0 | 1.0000 | +.00006 | PASS(무해) |

챔피언은 이미 도메인 용어를 .9429 로 맞히므로 **고칠 것이 8건뿐**이고, 후보정은 이득 0 에 CER 만 유의하게
악화시킨다(CI 가 통째로 양수). 즉 **STT 승격이 오면 이 갈래의 값은 사라진다** — 후보정은 base 좌표에서만
말이 되는 임시 보정이다. agents 는 게이트웨이 diarize 가 `:8102` base 고정이라 지금은 base 좌표에 있다
([[stt-diar-path-base-fixed]]).

## 5. 결론 · 처방

> **후속(같은 날)**: 여기서 지목한 카탈로그 처방을 실제로 적용해 다시 쟀더니 사전 등록 기준을 **통과**했다 —
> precision(lenient) .8298→.9464, ΔCER −.00142 [−.00239,−.00059]. [`catalog-prescriptions-2026-09-08.md`](./catalog-prescriptions-2026-09-08.md).
> 아래 결론은 그 처방 **이전** 좌표의 것이다.

**채택하지 않는다. `TERM_FIX_ENABLED` 는 off 로 둔다.** 사전 등록한 대로 미달이면 종결이고, 프롬프트를 더
돌려 5건에 맞추지 않는다.

다시 열 조건은 하나다 — **카탈로그**. 오탐 8건 중 6건이 카탈로그 쪽 문제였고, 그건 프롬프트로 못 고친다.

1. **카탈로그 표제 규약** (`jinong_gpu`, `stt-041` 처방 ① 확장): 농약상표의 **회사명 접두 87건** 제거
   (`팜한농포리캡탄`→`포리캡탄`), 숫자 접미 11건은 맨 표기 병기. 코드 변경 0, `strip_legal_prefix.py` 확장.
2. **카탈로그 구멍 보강**: 실통화에서 발화됐지만 표제에 없는 상표 — `레일단`, `돌격제`, `아리커`,
   `총채싹플러스`, `풀마기골드`, `헬리앤드론`, 그리고 상위어 `가루이`·`이리응애`,
   생리장해 `팁번`, 재배용어 `활착기`·`급액`, 성분명 전무(`아족시스트로빈`). 하네스가 두 갈래로 내놓는다 —
   `out/term-fix-calls-base/catalog_queue.tsv`(LLM 이 냈으나 표제에 없어 거부된 39건) + 리포트의
   "오탐이 가리키는 카탈로그 문제" 표(정답 발화와 나란히).
3. 위 둘이 반영되면 같은 커맨드로 재측정한다 — 판정 기준은 그대로 두고 카탈로그만 바꾼 1-변수 A/B 다.

**agents 관점의 다른 시사점**

- `:8105` 축이 닫힌 뒤에도 **용어 회복 자체는 남아 있는 문제**다(base 좌표 오청 27건). 다만 그 크기가
  140발생·84통화에서 27건이라 **CER 로는 영원히 안 보인다** — 영농일지 추출이 그 27건을 얼마나 쓰는지가
  진짜 판단 근거이고, 그건 judge 축에서 봐야 한다(5건 on/off 에서 coverage +0.4~0.8, `docs/stt-term-fix-2026-09-06.md`).
- 골드 정제(538→140)와 회사명 접두 87건은 `jinong_gpu` stt-043(LBL)·카탈로그 축에 그대로 넘길 산출물이다.
  이 레포는 파일만 만들고 그쪽은 건드리지 않았다.
