# STT 후처리(용어 자동교정 + `:8105` 컨텍스트 경로) 전/후 — agent 평가(voice_eval) 비교 (2026-09-02)

## 왜 했나 / 전제 사실

게이트웨이(`jinong_ai-gateway`)가 2026-09-02 전사 응답에 **용어 자동교정(후처리)** 을 배선하고(`c2f1aec`, 내용변경 가드 `f54ad70`),
offline 전사/화자분리를 **Context Retrieval Layer `:8105`(2-pass 용어 컨텍스트)** 로 라우팅하기 시작했다(18:01 이미지 배포,
원격 `.env` `STT_CTX_URL=…:8105`, `TERMS_AUTOCORRECT` 기본 on, `min_score=1.0` = exact-only). agents 의 화자분리 경로는
`:8105 → :8102(qwen3-asr-diar, base) → :8104(pyannote)` + 세그먼트별 자동교정이 됐다.

이 문서는 (1) 같은 녹음 5건을 새 경로로 재전사·재평가해 8/27 기준선과 비교하고, (2) 자동교정이 **의도대로 들어갔는지** 검증한 기록이다.

- 기준선(전): `out/voice-eval-baseline-20260827/` — 2026-08-27 승인 기준선(`out/voice-eval.a3-accepted` 와 stt.json 동일), judge×3, 종합 **0.9033**.
  일지는 v1 형식으로 채점된 결과.
- 후처리(후): `out/voice-eval-postproc-20260902/` — 2026-09-02 `--force all` 재전사(운영 게이트웨이 0.2.0) → 파이프라인(gemini-3.5-flash,
  프롬프트 v2·일지 형식 v2 internal 변형) → judge(gemini-2.5-pro) **×3**. 같은 산출물의 judge×1 스크리닝은 `_judge1/`.
- STT 단 분석: `terms_analysis.md`(스크립트 `terms_analysis.py` 동봉) — 구/신 전사 CER·드리프트, 구 전사에 교정 엔진을 다시 건 반사실,
  신 전사 멱등성, 대본 내 사전 용어 인식률. 프로브 음성 응답 `probe_plain.json`/`probe_diar.json`.

| strawberry_microbial | 0.138 → 0.235 | 0.133 | 12/58 | 0 | 0건 | 0건 |

- 구 전사에 교정 엔진(`/v1/terms/correct apply=true`, 운영 설정)을 다시 걸어도 **치환 0건**, 신 전사에 걸어도 0건. 즉 구↔신의 모든 차이는
  자동교정이 아니라 **`:8105` 2-pass 경로 / ASR 자체의 변화** 다. 8/27 전사는 `:8102` 직행이었다.
- 이유는 구조적이다. 카탈로그 56,941건 중 `canonical ≠ term`(치환이 일어날 수 있는 항목)은 6,145건이고 그 구성이 품종 6,038 · 회사 87 ·
  **농약 상표 20**(`디티공칠→디티07` 같은 숫자 읽기형) · 병 0 · 해충 0 이다. exact-only 이므로 오인식(`크린캡→그린 프린탭`, `마쿠피카→마크업디카`,
  `나노-I→오노아이`)은 정의상 못 고친다 — 이번 judge 의 stt 귀속 감점이 정확히 이 유형이다. 엔진에 `그린 프린탭` 을 넣으면 `그린프릴`(0.9) 같은
  엉뚱한 후보만 나온다(fuzzy 완화가 전부 악화였다는 게이트웨이 캘리브레이션과 일치).
- 대본 내 사전 용어 exact 인식률(농약·병·해충 24종)은 0.625 → 0.708 (`다코닐`·`다코닐에이스` fuzzy→exact, `에이플` fuzzy→miss). 이것도 자동교정이 아니라
  `:8105` 컨텍스트 경로의 효과(또는 편차)다.
- 어절 병합형 치환(가드 위반 후보) 0건.

## 자동교정이 의도대로 들어갔나 — 검증 체크리스트

| 항목 | 확인 방법 | 판정 |
|---|---|---|
| 운영 게이트웨이가 후처리 버전 | `/healthz` 0.2.0, 이미지 빌드 18:01(가드 커밋 17:58 이후), `/v1/upstream/health` 에 `ctx` 항목(`b126216`) | ✅ |
| `:8105` 경로 활성 | 원격 `.env` `STT_CTX_URL`, upstream health `ctx: ok` | ✅ |
| 교정 엔진 라이브·설정 | `/v1/terms/correct` 에 `다이센엠사오/디티공칠/론사공공` → `다이센엠-45/디티07/론400` 3건 치환(score 1.0), `다이센엠45`·`론4000` 은 가드로 미치환 | ✅ |
| 전사 경로에서 자동교정이 실제로 동작 | TTS 프로브(`다이센엠사오…디티공칠…론사공공`) → 일반 전사 `다이센엠45 … dt07 … 론4000`(`corrections` 없음), 화자분리 `다이센엠45하고 DT07을 … 론400` | ⚠ 직접 증거 없음 — ASR/`:8105` 가 이미 숫자형으로 내놓아 exact-only 교정기가 볼 span 이 없다 |
| 실녹음 5건에 미친 효과 | 반사실·멱등성 0건 | **0 (무효과)** |
| 교정 내역이 agents 응답에 노출 | 화자분리 응답 변환 `_diar_to_chunks`(`app/routes/transcriptions.py`)가 `corrections` 키를 버림 | ❌ 갭 |
| 오인식 복구 | exact-only + canonical 집합이 숫자 읽기형 위주 | ❌ 설계상 범위 밖 |

정리: **배선은 들어갔고 엔진은 살아 있지만, agents 경로의 실녹음에서는 아무것도 바꾸지 않는다.** 이번 비교에서 관측된 변화(CER 3/5 악화, faithfulness 하락,
사전 용어 exact 인식률 소폭 상승)는 전부 `:8105` 컨텍스트 경로(및 ASR 편차) 몫이며, 자동교정과 `:8105` 를 같이 켰기 때문에 이 데이터만으로 둘을 분리할 수는 없다.

## 해석 · 권고

- **agents 쪽 조치 없음.** 프롬프트·매핑·임계값을 건드릴 근거가 아니다(`stt` 귀속은 프롬프트로 해결 불가, 재현율·발생단계는 동일). 자가 개선 루프 기준선은
  0.9033 유지하되, **STT 경로가 바뀌었으므로 다음 측정은 반드시 짝지은 기준 재측정과 함께** 한다(구 stt.json 캐시로 재는 값과 새 전사로 재는 값은 다른 기준선).
- 게이트웨이에 제안(이 리포 밖):
  1. `_diar_to_chunks` 가 `response.corrections` 를 전달하게 — 그래야 운영 통화에서 자동교정이 실제로 뭘 바꾸는지 관측된다(지금은 반사실로만 검증 가능).
  2. `:8105` 단독 효과 측정 — dev 게이트웨이에서 `STT_CTX_URL` 을 비운 채 같은 5건을 재전사해 CER 0.131→0.166 악화가 경로 탓인지 ASR 편차인지 가른다.
     8/28 A/B(`docs/voice-eval-stt-ab-2026-08-28.md`)와 같은 방법으로 두 팔을 짝지어 재면 된다.
  3. 오인식 복구를 기대한다면 exact-only 자동교정이 아니라 카탈로그 canonical 확장(상표 이형 표기)이나 `:8105` 컨텍스트 주입 쪽이 맞는 자리다.
