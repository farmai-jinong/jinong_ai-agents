## 왜 했나 / 전제 사실

게이트웨이(`jinong_ai-gateway`)가 2026-09-02 전사 응답에 **용어 자동교정(후처리)** 을 배선하고(`c2f1aec`, 내용변경 가드 `f54ad70`),
offline 전사/화자분리를 **Context Retrieval Layer `:8105`(2-pass 용어 컨텍스트)** 로 라우팅하기 시작했다(18:01 이미지 배포,
원격 `.env` `STT_CTX_URL=…:8105`, `TERMS_AUTOCORRECT` 기본 on, `min_score=1.0` = exact-only). agents 의 화자분리 경로는
`:8105 → :8102(qwen3-asr-diar, base) → :8104(pyannote)` + 세그먼트별 자동교정이 됐다.

이 문서는 (1) 같은 녹음 5건을 새 경로로 재전사·재평가해 8/27 기준선과 비교하고, (2) 자동교정이 **의도대로 들어갔는지** 검증한 기록이다.

- 기준선(전): `out/voice-eval-baseline-20260827/` — 2026-08-27 승인 기준선(`out/voice-eval.a3-accepted` 와 stt.json 동일), judge×3, 종합 **0.9033**.
  일지는 v1 형식으로 채점된 결과.
- 후처리(후): `out/voice-eval-postproc-20260902/` — 2026-09-02 `--force all` 재전사(운영 게이트웨이 0.2.0) → 파이프라인(gemini-3.5-flash,

정리: **배선은 들어갔고 엔진은 살아 있지만, agents 경로의 실녹음에서는 아무것도 바꾸지 않는다.** 이번 비교에서 관측된 변화(CER 3/5 악화, faithfulness 하락,
사전 용어 exact 인식률 소폭 상승)는 전부 `:8105` 컨텍스트 경로(및 ASR 편차) 몫이며, 자동교정과 `:8105` 를 같이 켰기 때문에 이 데이터만으로 둘을 분리할 수는 없다.

- **agents 쪽 조치 없음.** 프롬프트·매핑·임계값을 건드릴 근거가 아니다(`stt` 귀속은 프롬프트로 해결 불가, 재현율·발생단계는 동일). 자가 개선 루프 기준선은
  0.9033 유지하되, **STT 경로가 바뀌었으므로 다음 측정은 반드시 짝지은 기준 재측정과 함께** 한다(구 stt.json 캐시로 재는 값과 새 전사로 재는 값은 다른 기준선).
- 게이트웨이에 제안(이 리포 밖):
  1. `_diar_to_chunks` 가 `response.corrections` 를 전달하게 — 그래야 운영 통화에서 자동교정이 실제로 뭘 바꾸는지 관측된다(지금은 반사실로만 검증 가능).
  2. `:8105` 단독 효과 측정 — dev 게이트웨이에서 `STT_CTX_URL` 을 비운 채 같은 5건을 재전사해 CER 0.131→0.166 악화가 경로 탓인지 ASR 편차인지 가른다.
     8/28 A/B(`docs/voice-eval-stt-ab-2026-08-28.md`)와 같은 방법으로 두 팔을 짝지어 재면 된다.
  3. 오인식 복구를 기대한다면 exact-only 자동교정이 아니라 카탈로그 canonical 확장(상표 이형 표기)이나 `:8105` 컨텍스트 주입 쪽이 맞는 자리다.

  `알이랑 → 아리랑`(교란어 `아리랑`), 잡담 줄들의 미세 변형(`사람을 먹고 → 사람을 못 구해서` 처럼 좋아진 것도, `본포 → 봄 포` 처럼 나빠진 것도).
